# Global Data Centers (site code)

The code behind [floridadatacenters.org](https://floridadatacenters.org), now Global Data Centers: an independent site that tracks data center projects and gives residents tools to respond to them.

This repo is a snapshot of the production branch with a fresh history. Secrets, customer records and personal email addresses were removed before the first commit.

## What the site does

- **Project, company and place pages.** About 1,465 project pages, 89 company pages and 1,163 place pages, each built from sourced records.
- **3D globe.** Every tracked site on an interactive globe, with a static image fallback for phones.
- **Address risk tool.** A visitor enters an address and gets a report on nearby projects and local risk factors, served from precomputed lookup tiles.
- **Letters to officials.** A resident can have an opposition letter drafted and sent to their county commissioners, free or paid.
- **Paid products.** A preparation brief generated after payment, and a merchandise shop fulfilled by a print-on-demand provider.
- **Reports and alerts.** Visitors can report a project; subscribers get email alerts.

## How it is built

- **Front end:** plain HTML, CSS and JavaScript. No framework. The globe uses a vendored copy of globe.gl.
- **Pages:** generated by Node scripts in `data/` (`build-pages.js`, `build-globe.js`) from JSON records.
- **Back end:** Cloudflare Pages Functions in `functions/`, with a KV namespace for stored reports and orders.
- **Services:** Stripe for payments and webhooks, Brevo for email, Printify for merchandise, Geoapify and Google Maps for geocoding, Gemini for drafting.
- **Checks:** scripts in `tools/`, mostly Playwright, plus `tools/check-order-reliability.mjs`, which runs the order and webhook code against stubbed Stripe and email services.
- **Hosting:** Cloudflare Pages, deployed from the `main` branch.

## Running it locally

```
npm install
cp .dev.vars.example .dev.vars     # then fill in your own keys
npx wrangler pages dev .
```

The static pages also open directly from disk. `npm run build` regenerates the globe data and the pages.

All keys are read from environment variables; `.dev.vars.example` lists them with placeholder values. Payment, email and fulfilment functions need real keys for those services.

## What is not in this repo

- API keys and `.env` files.
- Customer names, emails, addresses and orders.
- The raw GIS downloads the risk lookup tiles were built from.
- The satellite map stills shown on project pages (`map-img/`). They come from a third-party map provider, so pages in this repo reference images that are not included.
